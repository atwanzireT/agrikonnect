# AgriKonnect Farmer Mobile API + Offline Sync

This upgrade keeps the existing web platform and adds a professional farmer mobile API layer for farm management, produce marketing, and offline-first mobile apps.

## Main endpoints

All authenticated endpoints use:

```http
Authorization: Token <token>
```

### Authentication

- `POST /api/farmers/login/` — login using phone/email and password.
- `POST /api/farmers/logout/` — revoke token.
- `GET /api/farmers/me/` — current farmer profile.

### Farmer dashboard

- `GET /api/farmers/dashboard/` — farm count, activities, harvest, expenses, sales, and estimated profit.

### Farm management APIs

- `/api/farmers/farms/`
- `/api/farmers/activities/`
- `/api/farmers/harvests/`
- `/api/farmers/expenses/`
- `/api/farmers/sales/`

Each supports list, create, retrieve, update, patch, and soft delete.

### Marketplace APIs

- `/api/farmers/listings/` — farmer creates produce listings for buyers.
- `/api/farmers/buyer-requests/` — farmer views open buyer demand. Optional filters: `?crop=coffee&district=Kasese`.
- `/api/farmers/listing-inquiries/` — farmer views buyer inquiries on their listings.

## Offline-first support

The farm management models now include:

- `client_id` — ID generated by the mobile app while offline.
- `client_updated_at` — timestamp from the mobile device.
- `sync_status` — server sync state.
- `is_deleted` — soft delete flag.

### Pull changes since last sync

```http
GET /api/farmers/farms/?updated_since=2026-05-22T10:00:00Z&include_deleted=true
```

Works for farms, activities, harvests, expenses, and sales.

### Bulk sync endpoint

```http
POST /api/farmers/sync/
Content-Type: application/json
Authorization: Token <token>

{
  "last_sync_at": "2026-05-22T10:00:00Z",
  "farms": [],
  "activities": [],
  "harvests": [],
  "expenses": [],
  "sales": []
}
```

The response returns:

- `server_time` — save this on the mobile app as the new last sync time.
- `uploaded` — records accepted by the server.
- `download` — server records changed since `last_sync_at`.
- `errors` — validation or conflict errors per local `client_id`.

## Mobile offline implementation guide

In Flutter/React Native, store records locally in SQLite/Hive/Isar with the same fields. When offline, create records with a UUID `client_id` and mark them as pending locally. When internet returns, call `/api/farmers/sync/`, then replace local records using the server `id` and save the returned `server_time`.

## Migration

Run:

```bash
python manage.py migrate
```

If you are deploying on a fresh server, also run:

```bash
python manage.py collectstatic
```
